## Goal

The phone owner (person with `is_me = 1`) has their weigh-ins assigned automatically and written to Health Connect. Anything not close to their weight is saved, left unassigned, and triggers a "Whose weigh-in?" notification. The second person is added in a later round. The assignment code must already handle two people, so that round only adds a person row.

## Steps

### 1. Assignment rule (pure Kotlin, test-first)
New file `Assign.kt`: `fun assign(weightCentiKg: Int, refs: Map<Long, Int>): Long?`, where `refs` maps person id to reference weight in centi-kg.
- Find the nearest person, at distance `d1`, and the second nearest, at `d2` (infinite if there's only one person).
- Return the nearest id when `d1 <= 300 && d2 - d1 >= 200`. Otherwise return `null`. No people means `null`.

Write `AssignTest.kt` **before** the code. Cover:
- one person 66.30 kg: reading 67.65 → assigned; 69.31 → null; 63.30 (exactly 3.00 kg away) → assigned
- two people 66.30 and 80.00: 67.00 → first; 79.00 → second; 73.00 → null
- two people 66.30 and 67.50, reading 66.90 → null (margin under 2 kg)
- empty map → null

Verify: the tests fail before the code exists and pass after.

### 2. Database v2 (`Db.kt`)
- Bump the version to 2. `onCreate` creates the full v2 schema. `onUpgrade` from 1 runs **only** the statements below. Existing readings must survive, and they stay unassigned (`person_id` NULL).
  - `CREATE TABLE person (id INTEGER PRIMARY KEY, name TEXT NOT NULL, start_weight_centi INTEGER NOT NULL, is_me INTEGER NOT NULL)`
  - `ALTER TABLE reading ADD COLUMN person_id INTEGER`
  - `ALTER TABLE reading ADD COLUMN hc_written INTEGER NOT NULL DEFAULT 0`
- `saveIfNew` returns the new reading id (`Long?`, null when not saved) instead of `Boolean`.
- Add `Reading.id` and `Reading.personId` fields. Update `latest()` to select them.
- New functions, kept minimal: `me()`, `people()`, `addPerson(name, startWeightCenti, isMe)`, `refs()` (each person's latest assigned reading weight, else their start weight), `setPerson(readingId, personId)`, `markWritten(readingId, written)`, `delete(readingId)`, `reading(id)`, `pendingForMe()` (readings of the `is_me` person with `hc_written = 0`).

### 3. Health Connect (`HealthConnect.kt`)
- `client(context)`: returns `HealthConnectClient.getOrCreate(context)` when `getSdkStatus(context) == SDK_AVAILABLE`, else null.
- `PERMISSIONS = setOf(HealthPermission.getWritePermission(WeightRecord::class))`
- `suspend fun write(context, r: Reading)`: inserts a `WeightRecord` (time = `takenAt`, weight = `Mass.kilograms(centi / 100.0)`, `clientRecordId = "reading-<id>"`, device type scale). In 1.1.0 metadata is built with the `Metadata.autoRecorded(...)` factory, so check the actual API in the jar. On success, call `markWritten(id, true)`.
- `suspend fun remove(context, readingId)`: `deleteRecords(WeightRecord::class, emptyList(), listOf("reading-<id>"))`.
- `suspend fun syncPending(context)`: write every `pendingForMe()` reading. This is the retry path if a background write failed or permission came later.
- Catch exceptions from Health Connect calls. Log them with tag `Bloblog` and leave `hc_written = 0`. Never crash, and never lose the reading.

### 4. Capture path (`Scanner.kt`, `ScanReceiver`)
Use `goAsync()` plus a coroutine on `Dispatchers.IO`, with `finish()` in `finally`. For each saved reading:
1. `personId = assign(weight, db.refs())`, then `setPerson`.
2. If it's `me()`, call `HealthConnect.write`.
3. If `personId == null`, post the notification (step 6).

### 5. Manifest
- Add `android.permission.health.WRITE_WEIGHT` and `android.permission.POST_NOTIFICATIONS`.
- Add `<queries><package android:name="com.google.android.apps.healthdata" /></queries>`.
- Add the Health Connect rationale entry points, or the permission request silently fails:
  - New `PrivacyActivity`, a plain `Activity` with one TextView reading `Blob-log saves your weight from your scale to Health Connect. It doesn't read any Health Connect data, and nothing leaves your phone.` Exported, with an intent-filter for `androidx.health.ACTION_SHOW_PERMISSIONS_RATIONALE`.
  - An `activity-alias` named `ViewPermissionUsageActivity` targeting `PrivacyActivity`. Exported, `android:permission="android.permission.START_VIEW_PERMISSION_USAGE"`, with an intent-filter for action `android.intent.action.VIEW_PERMISSION_USAGE` and category `android.intent.category.HEALTH_PERMISSIONS`.

### 6. Notification (unassigned only)
- Channel id `unassigned`, name `Unassigned weigh-ins`, default importance. Create it on demand.
- Title `Whose weigh-in?`. Body `67.65 kg at 07:42 — tap to choose.`, built from the reading with `%.2f` and `HH:mm`.
- Tapping opens `MainActivity` with extra `reading_id`. Use an immutable PendingIntent with request code = reading id. Notification id = reading id. Auto-cancel.
- Skip silently if the notification permission isn't granted.

### 7. `MainActivity` → `ComponentActivity`
Keep the existing layout approach and status-line texts. Add:
- **Setup**: if `me()` is null, show a non-cancelable AlertDialog titled `Who uses the scale?` with two EditTexts, hint `Name` and hint `Current weight (kg)` (decimal input), and a button `Next`. Weight outside 20–250 kg shows `Enter a weight between 20 and 250 kg.` and keeps the dialog open. On success, call `addPerson(name, centi, isMe = true)`.
- **Permissions**, in order, each requested only after the previous one is settled:
  1. Bluetooth: the existing `Allow Bluetooth` button.
  2. Notifications: request `POST_NOTIFICATIONS` once Bluetooth is granted. No extra UI.
  3. Health Connect: a banner TextView `Health Connect isn't connected. Readings are saved here but not sent.` with a `Connect` button. It's visible when the client exists and `PERMISSIONS` aren't all granted. The button launches `PermissionController.createRequestPermissionResultContract()` via `registerForActivityResult`. If Health Connect isn't available, show `Health Connect isn't available on this phone.` instead, with no button.
- **onResume**: `lifecycleScope.launch { HealthConnect.syncPending(this) }`, then refresh.
- **Rows**: `Sat 22 Nov · 07:42    67.65 kg    Alex`, or `Who's this?` instead of the name when unassigned.
- **Row tap** (and launch with extra `reading_id`): AlertDialog titled `Whose weigh-in?` with one item per person (their name) plus `Not us — delete`.
  - Choosing a person calls `setPerson`. If that's the `is_me` person and not yet written, write to Health Connect. If moving **away** from `is_me` and it was written, remove it from Health Connect and mark it unwritten.
  - Delete removes it from Health Connect first if it was written, then deletes the row.
  - Both actions cancel the notification with that id and refresh the list.
